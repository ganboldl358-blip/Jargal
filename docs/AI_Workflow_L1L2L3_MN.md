## 0. Товч дүгнэлт

1. **Үлдсэн ажлын 97 % нь монгол эхтэй** (5000, 5020, 5172 ≈ 1,711 хуудас). Монгол эхийн L2 бол орчуулга биш: мөр нийлүүлэх, иш татах, гар засвар оруулах, нэр томьёог жигдлэх ажил. **Үүнийг `l2_auto.py` скрипт LLM огт хэрэглэхгүйгээр хийнэ.** Grok-д үлдэх ажил нь зөвхөн орос эхийн L2 (1853-ын үлдсэн ≈42 хуудас, мөн цаашид ирэх орос тайлан) болон маргаантай тоог дахин шалгах ажил. Grok-ийн лимитийг хэмнэх хамгийн том арга нь энэ.
2. **L1-ийг Gemini Pro хийнэ.** Grok Build-ийг L1-д хэрэглэхгүй: туршилтад 2 хуудсыг ≈7 минутад уншсан, монгол үгийг андуурсан, хуудасны дугааруудыг сольсон. Gemini-ийн гаргадаг алдаа (грек үсэг, кириллээр бичсэн химийн тэмдэг) машинаар илэрдэг бол Grok-ийн алдаа (буруу уншсан үг) илэрдэггүй.
3. **Автоматжуулалт.** Чат ботууд (Gem, Grok Project) Drive-д файл хадгалж чаддаггүй. Иймд «үр дүнг тэнд хадгал» гэж зааж өгөх нь ажиллахгүй, хэн нэгэн хуулж тавих хэрэгтэй болдог. Жинхэнэ автоматжуулалт нь Jak-ын компьютер дээр ажиллах **Gemini API скрипт** юм: `py queue_tool.py auto --rows 5 --with-l2`. Энэ команд QUEUE-гээс мөр авч, L1 хийж, монгол эх бол L2_AUTO хийж, QA ажиллуулж, QUEUE-г шинэчилнэ. Чатын квот, Claude-ийн токен зарцуулахгүй бөгөөд хуулж тавих ажил байхгүй. Зардал нь ≈1,700 хуудсанд ойролцоогоор $30–60 (одоогийн үнийг заавал шалгах, §3).
4. **Claude-ийн токеныг хэмнэх.** Claude-аар Gemini, Grok-ийн вэбийг browser-оор жолоодуулахаа болино. 26 KB хэмжээтэй QUEUE-г Claude уншиж, дахин бичихээ болино (`queue_tool.py` хийнэ). QA-г LLM-ээр хийлгэхээ болино (`qa_check.py` хийнэ). **Claude зөвхөн L3 хийнэ**, тэгэхдээ L2 болон хүснэгтийн CSV-ээс л уншина.

## 4. Лимит, токен хэмнэх дүрэм

### Grok
1. Grok-т зөвхөн **орос эхийн L2** болон **маргаантай тоог зурагтай дахин уншуулах** ажлыг өгнө. L1 хийлгэхгүй. Монгол эхийн L2-ыг ч хийлгэхгүй.
2. `L2_INSTRUCTIONS.md` болон glossary-г **«Geo L2» Project-ийн instruction/файлд нэг удаа** тавина. Чат бүрт зөвхөн `py queue_tool.py next L2`-ийн хэвлэсэн 2 мөр prompt-ыг хуулна.
3. Prompt бүрт 5–6 хуудас өгнө. **QUEUE-ийн мөр бүрт шинэ чат** нээнэ: чат уртсах тусам хариулт удааширч, чанар муудна.
4. Grok-ийн «Fast» горимыг 1 мөр дээр туршиж, `qa_check.py --l1`-ээр Expert-тэй харьцуулна. Тоон зөрүүгүй гарвал Expert-ийн лимитийг хэмнэнэ.

### Gemini (апп/Gem)
5. L1 API руу шилжсэний дараа Gem-ийн квотыг L1-ийн нөхөлт болон L3 ноорогт (cards, хураангуй) хэрэглэнэ.
6. Gemini-гаар L2 хийлгэхгүй (≈4–5 %/prompt).

### Claude
7. **Gemini, Grok-ийн вэбийг Claude-аар browser/computer-use-ээр жолоодуулахгүй.** Дэлгэцийн зураг бүр их токен иддэг. `L1L2_QUEUE.md`-ийн log-т тэмдэглэгдсэн routine, browser session, Google блокууд нь яг ийм ажлын ул мөр.
8. QUEUE-г Claude уншиж, бичихгүй. `py queue_tool.py summary` 10 мөр хэвлэнэ, Claude зөвхөн түүнийг уншина. Хоёр хоногийн дотор `L1L2_QUEUE.md`-ийн 25 гаруй `_OLD_` хуулбар үүссэн. Хуулбар бүр 26 KB файлыг бүтнээр нь уншиж, дахин бичсэн гэсэн үг.
9. QA-г LLM-ээр хийлгэхгүй. `qa_check.py` ажиллуулж, Claude зөвхөн **ERROR** мөрүүдийг харна.
10. L3-ыг хийхдээ **зөвхөн L2 болон `tables_to_csv` CSV-ийг** уншина. PDF, зураг, L1-ийг qa_check анхааруулга өгсөн хуудсанд л харна.
11. Нэг тайлангийн хэсэгт нэг session нээнэ. Хэсэг бүрийн хураангуйг `07_Report_Summaries`-д файл болгон хадгалж, дараагийн session-д L2-ыг дахин уншихгүй (map → reduce).
12. Механик задлалтыг Sonnet subagent-аар, эцсийн синтезийг Opus-оор хийлгэнэ. Routine-ийг өдөрт 1 удаа, эсвэл Jak дуудахад л ажиллуулна.

## 6. L3-ыг хэрхэн зохион байгуулах вэ

Одоо байгаа L3: `06_Master_Reports`-д 1853-ын 12 хэсэг (`*_L3.md`), тус бүр `09_QA`-д QA файлтай. `07_Report_Summaries`-д 13 сегментийн `*_summary.md` + `*_cards.csv` байна.

1. **Бүтэцтэй өгөгдөл (LLM-гүй):** `tables_to_csv.py`-ийн гаргасан хүснэгтүүдийг (эрдэсжсэн цэг, солбицол, сорьц, шинжилгээ) `04_Structured_Data\tables\`-д хадгална. Claude эдгээрийг нэгтгэж, баганыг стандартчилж, GIS-д бэлдэнэ. Тоог LLM дахин бичихгүй.
2. **Хэсгийн хураангуй (map):** 20–40 хуудсаар хэсэглээд Sonnet subagent `cards.csv` болон богино хураангуй гаргана.
3. **Тайлангийн синтез (reduce):** Opus зөвхөн (2)-ын хураангуй болон (1)-ийн CSV-ийг уншиж `06_Master_Reports\<тайлан>_L3.md` бичнэ. Тоо бүрт `(тайлан, х.N)` иш заавал байна.
4. **1853 L3 засвар:** GROK_TO_CLAUDE-д заасан а/б/в индексийн ≈22 сэжигтэй газрыг (х.78, 93–96, 121, 135, 146, 246–252) L2_GROK/GROKFIX файлтай тулгана. Үүнийг эхлээд скриптээр (тоон жагсаалтын зөрүү) олоод, Claude зөвхөн зөрүүтэй мөрүүдийг засна.
